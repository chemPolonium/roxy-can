# 产品定位与体验准则

本文回答三个问题：这个软件**不做什么**、什么才算**功能欠缺**、以及改界面时**什么该做、什么不该做**。功能清单见 `README.md`，操作语义见 `docs/usage.md`，实现理由见 `docs/architecture.md`。

## 1. 定位

**CANoe 是能力上限，不是要超越的目标。**

roxy-can 是一个免费的、轻量的 CAN / FlexRay / 车载以太网**监测与简单自动化**替代品：

- 打开日志或工程就能看、能统计、能解码；
- 能录、能放、能发会话内报文；
- 能用触发器、Panel 和脚本做简单自动化；
- 一个人、一台笔记本、一个本地 Web UI 就能用。

不做完整 CANoe：不做诊断栈、不做 TSN/DoIP 全家桶、不做通用 HMI 框架、不做工业级测试报告、不做分布式测量。

### 能力边界

- **CAN / CAN FD**：监测、录制、回放、生成、Panel/Trigger 发送、DBC 解码。
- **FlexRay**：接收、解码、观测、录制、回放、会话内发送；真实端口发送未完成。
- **Ethernet**：ARXML/FIBEX 矩阵、BLF/PCAP/PCAPNG 回放、L2/PDU 解码、SOME/IP（UDP/TCP + SD）、PCAP/BLF Ethernet 录制、Npcap 实时口收发。
- **自动化**：触发器、Panel 按钮、脚本、系统变量；无头 CI 判定未完成。
- **不做**：诊断、TSN/DoIP 协议栈、通用 HMI、多机分布式、用户/权限、国际化、MF4、LIN。

## 2. 什么才算“功能欠缺”

先分清两类问题：

| 类型 | 例子 | 处理 |
| --- | --- | --- |
| **能力缺口** | Npcap 多口/时序仍需台架验证、FlexRay 发不出去、真实 Ethernet/SOME-IP 语料仍缺 | 记录在 `TODO.md`，按台架/真实样本推进；不靠加按钮解决 |
| **流程缺陷** | 同一个任务要从三个入口进、设置后不知道有没有生效、错误只闪一下 | 立刻修；优先于新能力 |

当前判断：**监测与简单自动化的主链路已经够用**。剩余能力缺口集中在真实硬件与 CANoe IL 级服务模拟，不适合继续堆界面功能。现阶段的主要空间在真实硬件与真实语料，不在协议广度。

## 3. 体验准则（硬规则）

1. **不新增顶层入口，除非同时删掉一个旧入口或至少省掉一步。**
   新按钮、新标签、新菜单必须回答：“它替代了哪一步？”答不上来就不加。
2. **一个任务只有一条明显路径。**
   同一件事不要同时存在于顶栏、右键、Setup 和弹窗里；确需快捷入口时，它必须调用同一条命令，不复制逻辑。
3. **默认简单，进阶折叠。**
   常用字段直接可见；pre/post、冷却、最大次数、物理值编码等放进 Advanced/More，不把主表单拉长。
4. **禁用必须解释，错误必须留在原地。**
   按钮为什么灰、文件为什么不能导入、动作为什么没发出去，要写在控件旁边或持久状态行，不能只靠 toast。
5. **术语统一。**
   - bus = 一路物理/虚拟总线；channel 只用于硬件通道。
   - frame = 线上帧；message = DBC 报文。
   - measurement = 一次 Start 到 Stop；run mode = Simulation / Replay。
   - service / method / event 只用于 SOME/IP。
   界面、文档、错误文案共用同一套词。
6. **表格先减列，再加行详情。**
   宽表横向滚动是最后手段；优先把低频列收进行展开/详情，不要为每类数据再加一列。
7. **空状态要告诉用户下一步。**
   “没有数据”后面必须跟一句“先打开工程 / 先 Start / 先导入 ARXML”。
8. **状态必须可见。**
   当前是 Simulation 还是 Replay、是否在测量、日志来自哪里、发送是否只进会话，都要在状态栏或控件附近说清楚。
9. **文档与代码同改。**
   功能变了，`README.md`、`docs/usage.md`、`TODO.md` 同一次提交更新；过时说法直接删，不保留“历史遗留”段落。
10. **界面风格保持窄边距、直角、无装饰阴影/渐变。**
   状态灯等小指示器保留圆形；新增组件不要引入圆角卡片、发光或大面积阴影。皮肤层在 `web/src/minimal.css`。

## 4. 当前体验债

1. **真实语料**：以太网/SOME/IP 仍缺一份真实 CANoe 语料回归；新增解析规则前先补样本，不靠合成 fixture 自证。

Panel 字段校验已就近保留；SOME/IP 发送已有 service/method 字段列表；service instance/eventgroup 已用于 Database 过滤；Trace/Messages 会按槽位宽度自动减列。

## 5. 改界面的验收清单

- 这个改动删掉了哪一步，或消除了哪个误解？
- 是否复用了已有菜单/组件/命令，而不是新建第二套？
- 默认值是否安全（新规则默认关闭、空配置不发送）？
- 禁用与失败是否在控件附近有持久说明？
- 1280×800 与 1024×768 下是否没有新增横向溢出？
- 相关文档是否已同步，过时句子是否已删除？
