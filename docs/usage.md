# 使用说明

各功能窗口的详细操作语义与口径。总览与快速上手见 `README.md`；语言参考见 `docs/script_language.md`；架构见 `docs/architecture.md`。

## 命令行（无头模式）

```
roxy-can                                  开窗口（默认）
roxy-can --replay <log.asc|blf> [...]     回放日志，不开窗口
roxy-can --project <p.rxproj> [...]       无头仿真整个工程
roxy-can --check-script <f.rxcan> [...]    校验节点脚本（flag 可重复）
roxy-can --convert <in.log> <out.asc>     BLF/ASC 转存为 ASC
roxy-can --kvaser-probe                   列出 canlib 可见的 Kvaser 通道
roxy-can --vector-probe                   列出 vxlapi 可见的 Vector 通道与总线类型；有 FlexRay 口时 RX 试开 2 秒
roxy-can --vector-probe --fibex <f>       先校验 FIBEX/ARXML 集群描述（报告波特率/槽数/触发项），再按它配置 RX 试开，并转储最多 8 个**互不相同**的事件头原始字节（定 A/B 通道偏移用）
roxy-can --export-csv <log> --out <csv>   无窗口导出信号 CSV：--dbc 可重复（按序合并），--fibex 可重复（**第 N 份描述第 N-1 路 FlexRay cluster**，一份日志可以真有两个 cluster），解不出的行数写在报告里
roxy-can -h                               完整帮助
```

- **`--replay`**：按日志时间轴回放；`--speed <n>` 倍速（默认 1.0），`--duration <s>` 到时即停（默认跑到日志末尾），`--stats <csv>` 结束后导出消息统计。回放自动静音同 ID 的发生器条目，不会两路混流。
- **`--project`**：无头仿真保存的工程——生成器与脚本节点按工程里保存的**条目开关**上线，且照常受**角色闸**（节点角色须为 `Simulated` 才真正发车；GUI 与 CLI 同一语义）。必须给 `--duration`，否则仿真没有终点。
- **`--profile <名>`**：叠加 `<工程目录>/profiles/<名>.toml` 里的**角色覆盖与硬件映射**，需配合 `--project`——同一套工程在 simulation / bench / CI 间零修改切换。角色词汇与工程一致（`Simulated` / `Absent`）；`[[hw]]` 声明"哪条总线接哪个通道"（波特率取总线自己的设置），**全量生效**：未列出的总线应用档案时解挂。GUI Network 窗口顶部的 Profile 行与此同源。Profile 只改角色，**不碰**生成器条目的 On 开关；写了不存在的总线 / 节点 / 角色词则**整份拒绝**（半套覆盖比没有更难排查），运行中止在任何发车之前；硬件打不开（适配器不在、驱动缺失）进状态行但不中止——角色覆盖独立成立。旧档案里的 `Monitor` 角色词已随两态化退役，含它的档案整份拒绝，请改存 `Absent`。格式：
  ```toml
  # profiles/bench.toml —— 被测件是真硬件，其余全模拟
  description = "bench rig"

  [[node]]
  bus = "Powertrain"
  node = "EngineECU"
  role = "Simulated"

  [[hw]]          # 可选：硬件映射（全量声明）
  bus = "Powertrain"
  channel = 0     # Kvaser 通道号
  ```
- **`--stats`**：结束时写出消息统计 CSV（bus, id, name, count, 周期 Min/Avg/Max, 长度, Flags）。
- **`--check-script`**：编译 `.rxcan` 节点脚本，全部通过退出码 0；任一失败退出码非 0 并列出 `line N:M` 错误。通过时顺带打印**静态响应映射**（`on A` 经哪个定时器 → 回哪个报文）与**发送 / 接收集**——CI 门禁之外，也是一份脚本行为的自动摘要。适合放进 CI 或保存前钩子。配合 **`--dbc <路径>`**（可重复，按序合并，重名先到先得）与 **`--node <名>`**（脚本扮演的 DBC 节点名）时，GUI 节点启动时的同一套装配检查在无头侧照跑：信号引用、发送集对照、反向漏实现、`set_sig` 字面量范围（系统变量检查需要管理器状态，仅 GUI 侧）。`[check]` / `[info]` 只进报告不改退出码——门禁的硬失败仍是编译错误。
- release 版无控制台窗口：从终端启动时会自动认领父控制台输出报告。
- **边界**：回放模式不支持录制——核心有意在回放启动时丢弃录制状态（录回放只会复刻日志）。

## 仿真节点（脚本编辑器）

- 脚本节点在 **Network** 视图的节点详情里创建："+ 脚本节点"（**绑定**到该 DBC 节点，总线跟随节点）。创建后自动弹出该节点的**独立脚本编辑器**（标题"脚本 · 节点名"，可多开）。树形拓扑里节点下面挂的就是它的脚本叶，点击即开编辑器。
- **绑定与角色闸**：脚本一律**依附于一个 DBC 节点**（Network 节点详情"+ 脚本节点"创建，绑定随工程保存）——所属节点角色不是"模拟"时，脚本同样**不发车**（`on start` / 定时器 / 事件发帧全被闸住），与生成器条目同一规则。旧工程的未绑定脚本在库加载时**自动收养**到该总线第一个库节点下。
- 编辑器内：改名、绑定显示（`节点 X · 总线 Y`，只读——脚本依附节点，没有总线选择）、**运行**开关、源码编辑、**Apply** 下发（测量中即时重编译重启该节点）、**保存/加载 `.rxcan`**、节点日志。点 Network 树里的脚本叶（或节点详情脚本列表的名字）可再次打开。
- **三栏布局（仿 CAPL Browser）**：**左栏**两个 tab——**大纲**（草稿里每个处理器/函数一行，带行号点击跳转，容忍没写完的源码）与**收发**（静态事实表：发送集按 DBC 归属标 `*` 本节点 / `!` 他节点 / `-` 不在库，接收集含 `*` 通配，访问的系统变量，响应映射）；**中栏**源码编辑 + Apply/保存/加载 + 节点日志；**右栏**四个插入 tab——**函数**（可点击插入的模板 + 本节点自己的 DBC 报文/信号）、**SysVar**（已定义的系统变量，一键插入读/写模板）、**报文**（本总线 DBC 声明的全部报文/信号，点选插入 `send`/`sig`）、**FlexRay**（各路描述解得出的信号，按"`名字 (FRn)` slot N · 帧名"分组（编号一并印出来：插入的就是那个编号）；点选插入 `fr_sig(n, N, "名")`——三个参数都不必让人另开窗口去查）。**FlexRay 单独一个 tab 而不是塞在"函数"下面**：它和"报文"是同一类东西（本工程里能被读的信号清单），而且它长——一个真实集群动辄上百个槽，混在模板列表里会把模板挤出面板。
- **源码区**（基于 ImGuiColorTextEdit 的语法编辑器控件）：Lua 语法的实着色（关键字/数字/字符串/注释），行号栏、空格浅色圆点、括号匹配、自动缩进、撤销/重做与查找替换（编辑器自带快捷键）；编译出错的行整行红底加行号红条标出（悬停可见错误全文，另见大纲/收发 tab 顶部与节点日志）。字体按显示密度动态光栅化，高 DPI 下依然锐利。
- **装配层检查**（Apply / 测量启动时进节点日志与 Write 窗口）：`sig` / `set_sig` 引用的信号须在 DBC 中；发送集对照 DBC 发送者声明（发了别家/不在库的报文 → `[check]`）；**反向漏实现**——DBC 声明本节点发送、脚本从不发送的报文 → `[info]`（生成器代发是常态，通配脚本豁免）；`set_sig` 字面量值超出 DBC 声明范围 → `[check]`（`min==max` 视为未声明界限）；引用未定义的系统变量 → `[check]`。
- 事件：`on start`（测量启动一次）、`on message <id>`（含 `*` 通配收所有数据帧）、`on extended message <id>`（显式扩展帧，数值可 ≤ 0x7FF）、`on fr slot <槽>` / `on fr <路> slot <槽>`（**FlexRay 帧到达**：该路那个槽每来一帧跑一次，路号不写就是所有路——节点绑在 CAN 通道上，FlexRay 帧没有 CAN 通道可匹配，所以路号是唯一的过滤）、`on errorFrame`（错误帧）、`on timer <ms>`（周期）、`on timer "名"`（一次性，`set_timer("名", ms)` 武装、`cancel_timer("名")` 取消，任意回调可调）。
- **FlexRay 事件里的帧上下文**：`frame_id()` 是**槽号**、`frame_dlc()` 是载荷字节数、`frame_byte(i)` 读载荷、`fr_cycle()` 给这次到达的通信周期号（CAN 处理器里没有周期，读回 0）。寻址用槽而不是帧名，是因为一个静态槽按周期相位轮流排好几帧——处理器读到的是**实际到达那一帧**（`fr_sig(路, 槽, "名")` 也按它解码）。写方向两种都有：`send` 从节点自己的 CAN 通道出去（"听 FlexRay、答 CAN"的网关形状），`fr_send(路, 槽, 字节…|buf)` 与 `set_fr_sig(路, 槽, "名", 值)` 直接动 FlexRay（口径见《FlexRay 发车》一节与 `docs/script_language.md`）。`send(frame_id())` 在这种处理器里是编译错误，因为把槽号当 CAN id 发出去正是两套编号混用最典型的错。
- 节点会收到**自己发出的帧**：在通配/同 ID 处理器里无条件发帧会自激成环，务必用 `frame_id()` 过滤。
- 节点出错（编译或运行时）即**熔断停跑**，日志留原因；重新 Apply 或重启测量恢复。周期定时器错过的时间点收敛为一次触发，不补偿堆积。
- `print(...)` 输出到节点日志（200 行封顶，最新在下），并同步进入 **Write 窗口**（见下）。
- 脚本与工程一起保存；`examples/` 有一组可运行示例（心跳波形、延迟应答、信号监视、嗅探转发、错误监视、派生信号、系统变量联动），全部随语言回归测试保持可编译。
- **节点角色**：DBC 声明的**每个节点**（不限发送节点）都在 Network 里带**两态角色声明**——**模拟**（允许本工具以该 ECU 名义发车：名下报文按 DBC 声明的周期进入生成器，逐条可调）与**离线**（不模拟：未声明的节点一律离线，restbus 无需配置；真实节点的流量在 Real bus 模式下经挂接通道进来，或来自回放块）。选择器下方有当前角色的说明。**角色只是闸门**：它决定"允许不允许发车"，条目发不发还看生成器里逐条目的 On 开关（见交互式生成器节）——切换角色不改写开关，激励与载荷原样保留。

## 总线与数据库（Buses 窗口）

- 一条总线可挂**多个 DBC 文件**：主库之外可再附加若干个（拖放 DBC 到窗口 = 附加为扩展库；"Open..." 按钮替换主库）。解码与查名按库序进行，重名报文先到先得。
- **比特率是选的不是输的**：仲裁段下拉给常用值 `10/50/100/125/250/500/800/1000` kbit/s，FD 数据段给 `0（无 FD 段）/1000/2000/4000/5000/8000`——**选错比特率不会报错，只会把整条总线的帧全解成垃圾**，所以这里只给标准值；工程里已经存着的值一定在列表里（哪怕是非标准的 62/83，Kvaser 就支持这些），打开旧工程不会被"顺手改成标准值"。`0` 是可达的：经典 CAN 就该选它（以前只能打字，且 `max(1)` 把 0 吃掉了）。
- **两表同形，都用原生控件的默认样子**：列宽列序一致（第三列同为 190 px），单元格都是**值在第一行、动作在第二行**（长文件名会把同一行右边的按钮挤出格子，被裁掉的按钮等于没有）。总线名仍是原生输入框——**不去改原生控件的配色来硬凑"看起来像文本"**，手搓样式既不生效也难维护，两表的一致靠列布局与控件选型达成。附加的第二个及以后的 DBC 各占一行灰字 + 行内 `x`。
- **DBC 变更自动重载**：运行中每 2 秒校验和比对挂接库，外部修改自动生效；"模拟"节点在库里**新增**的发送报文会随之出现为生成器条目（**不自动发车**——开与不开由你决定）。
- DBC 列表随工程保存（主路径 + 附加路径），相对工程目录。

## 回放块（节点详情内编辑）

- **回放块依附于节点**：从 Network 节点详情的"+ 回放块"新建（自动绑定到该节点，默认只回放它的报文），树的节点下同步出现块叶。块的**全部编辑都在节点详情里**：行首 checkbox 启用/停用、x 删除、缩进行选日志文件（.asc / .blf）与可选 id 过滤（如 `100, 3F4x`，留空 = 该节点的全部报文），Apply 提交。
- **与全局 Replay 模式无关**：回放块是仿真模式下节点的一种驱动形态，不是"回放模式"的一部分——仿真照常跑，块的流量按录制间距混入总线。
- **运行语义**：测量启动时装载日志并按过滤器归一化时间（首帧记 0），随后与发生器共用仿真时钟，按录制时的帧间距发车；同 ID 的帧会进入聚合、负载、规格与触发判定——它们就是总线流量。**仅仿真模式生效**：回放模式下整份日志本来就是信号源，块保持静默，绝无二次投递。
- 载入失败（路径无效、过滤后无帧、节点不在库中）会**停用块并就地显示载入失败原因**，绝不静默吞掉。新块默认停用——加入不发车。
- 块声明随工程保存（含启用位），恢复时立即重载队列，坏路径在打开工程时就暴露。

## 交互式生成器（节点中心 + FlexRay 槽）

- **节点就是编辑单元**：一个 DBC 节点的全部发车手段——**生成器条目（交互式）与脚本**——都在 **Network 窗口的节点详情**里：点开节点即见角色声明、生成器条目（完整行能力：On / 周期 / FD / Send now / 信号拖拽 / 激励）、本节点报文的 Add、响应规则，紧接着是本节点脚本列表。树形拓扑里，节点下面挂的就是它的脚本叶（`*` 运行中 / `o` 已启用 / `.` 未启用 / `!` 出错，点击打开编辑器）。
- **总览窗口**：**View → Interactive Generator** 上半部是**未分配条目**（不属于任何 DBC 节点的手动条目）——搜索框、逐总线 All On/All Off 批量开关，以及**按 hex id 添加**（标准帧；扩展报文经库声明从它的节点进）。节点条目不挤在这里。
- **FlexRay 条目在 Network 里，跟着它的 ECU**（与 CAN 同一个形状，不另开窗口）：FlexRay 一节展开 `ECU (n)`，点一个 ECU，右侧详情就是它的生成器面板——下拉列出**描述把这路里哪些帧绑给它发送**（`slot 13  帧名`，同槽按周期相位排几帧就并列写出），Add 建条目。**"哪个节点发哪一帧"是 FIBEX/ARXML 声明的事**：描述没说的槽就没有条目可加（状态行点明缺的是哪一条：没加载描述 / 描述未调度这个槽 / 没说明这帧由哪个 ECU 发送），本工具**不猜归属、也不给一个飘在树外的条目**——所以"输入任意槽号"的入口刻意不存在。行的能力与 CAN 条目同一套：On / 周期按钮（弹窗草稿，Apply 才写入；与描述声明的周期不一致时多一个"描述 {n} 周期"按钮一键换回）/ Send now / 信号拖拽与激励（Ramp / Sine / Step / Random / Triangle / Counter，参数弹窗与 CAN 共用同一个）/ x 删除。
- **但"什么时候发"和"发多宽"两件事，FlexRay 与 CAN 不是一回事，所以这两处设定也不同**（其余界面刻意保持一致，降低理解负担）：
  - **周期按通信周期数计，不按毫秒**。静态槽在调度表排给它的那一拍发，能改的只有"每几个周期"（`cycle_repetition`），所以周期弹窗里 FR 那一支的输入框是**周期数**，旁边实时显示它等于多少 ms；行上的按钮写 `N 周期`（悬停给 ms 与理由）。CAN 的 `0 = 事件触发`在这里不存在——填 0 会被拒绝并说明"静态槽没有事件触发，要它不发用 On 勾选框"，行上也把旧的 `event` 字样换成 `不发`。**这一路没有描述（或没声明周期时间）时没有可数的网格**，弹窗退回按 ms 编辑，行上的 tooltip 说明原因。改周期数不是改调度表：槽号、相位、载荷宽度仍然归 FIBEX/ARXML，本工具不替你改。
  - **载荷宽度归调度表，不归打字的人**。hex 框接受的就是这个槽声明的字节数（`{n} 字节`写在框的悬停里）：填少了**补 0**、填多了**整笔拒绝**并把数字说清楚（不静默截断——截断后发出去的就不是打的字节）。CAN 那侧 DLC 跟着打的字节走，这里不跟。**条目的身份是 `(路, 槽)`**，与曲线、触发、手选集合、`fr_sig(路, 槽, "名")` 同一个三元组的前两元；一个槽一条目（同槽多帧是周期相位的事，不是两条激励）。树里的 ECU 行 = 描述声明的 ECU ∪ 现有条目上盖着的 ECU 名，所以换掉或撤掉描述不会把用户搭好的激励藏起来。
- **FlexRay 条目发的是"本会话的流量"，不是线缆上的帧**：FlexRay 端口目前只收（`xlFrTransmit` 未接，见 TODO S5），所以生成的帧从接收侧灌进会话——Trace/Messages/Statistics、负载与规格监视、触发器、`on fr slot` 脚本、录制文件全都看得见（走的是与真到达同一个 `accept_fr_row`），但它不出端口、也不会被另一台设备收到。面板标题与行上的 chip 悬停就把这句说出来，不假装能发车。**没有角色闸**：角色是 DBC 节点的概念，FlexRay 侧没有，所以条目只有 On 与 MUTE 两种静默状态。**脚本同一个口径**：`fr_send(路, 槽, …)` 发的帧走同一个漏斗进会话（同样不出线缆），宽度也归该槽的调度声明——短了补 0、长了**整帧丢弃**并在节点日志里写明"声明 N 字节，脚本给了 M"，发给**没配置的路**（既没描述也没监听）同样整帧丢弃并说明先加载描述或挂监听（不然 Buses 表会多出一行，替打错的脚本编出一条没人收的总线）；`set_fr_sig(路, 槽, "名", 值)` 就是把 Network 里 ECU 面板改一个信号值的那一下写从脚本做（改的是条目"从现在起带什么"，条目 Off 就仍然什么都不发），没有条目 / 没有描述 / 这个帧不声明这个名字，整条写入丢弃并说明缺的是哪一件。
- **回放期间的静音与 CAN 同规则**：加载日志时一并扫出它带哪些 `(路, 槽)`（`scan_log_ids` 同时返回 CAN 与 FlexRay 两份集合），条目命中就在整个回放期间静默（chip 显示 MUTE，On 勾选框保持原样），退出回放照常——同一信号两个发送者混进每条曲线，是最难查的那种错。
- **新建条目默认关**，槽名、载荷长度与周期都取自该路的描述（周期 = 该帧的 `cycle_repetition × gdCycle`）；描述被移除后条目**照旧存在并发车**（行上写明"该路没有集群描述、或描述未调度这个槽：载荷按原样发出，无人解码它"），因为激励setup 是用户的，不该随一份文件消失。槽、周期、hex 载荷与信号激励随工程保存（`fr_tx` 一节，旧工程无此节即读为空）。
- **角色 = 总开关，条目开关 = 自定义**：一条目实际发车当且仅当——测量运行中、所属节点角色为**模拟**、条目 On、周期非 0（事件触发条目由触发器发车；FlexRay 条目没有事件触发这一说——周期 0 就是不发，见上一节）。角色切换**永不改写**逐条目的 On 开关；**新建条目默认关**（DBC 加载、重载补建、手动 Add 一律 inactive，开关状态随工程保存）；节点角色非模拟但条目开着时，面板摘要出"条启用 · 总关"、行内 chip 显示灰蓝"总关"——不发车的原因一眼可见。
- **载荷显示 = 最近一次实际发射**：行内 hex 与信号值读的是该条目**最近发出去的那一帧**（发射时算好存下，显示随消息周期跳变，不再逐帧重算）；从未发过的条目显示基准 hex。Send now 与触发 Send 同样刷新该值。
- 信号行：物理值拖拽编辑（被激励接管的信号只读，把激励改回 Constant 即解除）、激励类型下拉（Ramp / Sine / Step / Random / Triangle / Counter）、"..." 打开参数弹窗。

## 网络与角色（Network 窗口）

- **左右分栏**：窗口左侧是**树形拓扑区**，右侧是**所选节点的详情**（角色、生成器、脚本、收发信息）——选中的节点在左树里高亮，两栏各自滚动互不挤占。
- **拓扑区（TreeView）**：总线为根、DBC 节点为叶的树形目录——展开总线即见节点（默认展开）。节点行的角色色标：琥珀 `[S]` 模拟 / 灰 `[-]` 离线（悬停有说明）；名字后的绿 ● 表示"本次运行已见到它发车"。点击节点行，右侧详情打开该节点的一切。
- **节点详情 = 节点的全部**：角色两态下拉（下方常显当前角色的说明）、Simulate all / Stop all（本总线批量切角色——注意它们只切角色，**不会**替你打开生成器条目）、**生成器面板**（本节点条目的完整编辑、本节点报文的 Add、响应规则）、**本节点脚本**（`*` 运行中 / `o` 已启用 / `.` 未启用，点名字打开编辑器，"+ 脚本节点"新建即绑定）、**本节点回放块**（"+ 回放块"新建即绑定；checkbox 启用/停用、x 删除、就地选日志与 id 过滤）、Sent messages（实测计数与实测周期）、Received signals。一个节点发什么、怎么发、谁在发，一处看完。
- **FlexRay 集群在同一张树里**（CAN 通道之后）：一路一个根（根的名字就是 Buses 表里那一行的名字，没改名即 `FR{n}`），后面带该路描述的 cluster 名，没有挂描述就写"（无描述）"并说明为什么无从显示。**展开只有 ECU 一组**（描述里声明的 ECU 列表，**绑定得出发送者的那些还带"发 N 帧"**——只有 0 帧以外的数字会印出来，"描述没说"不等于"它不发"；描述里没有 ECUs 一节的（集群参数导出）就直说"未声明 ECU"。**点一个 ECU，右侧详情就是它的 FlexRay 生成器面板**——本工具里 ECU 叶不只是标签）。**这里刻意不排帧、不排槽**：一帧占哪个槽、哪个周期相位、重复几次是 FIBEX/ARXML 编辑器的事，本工具与它是分工关系（CANoe + Fibex Explorer 那种组合），在拓扑视图里再抄一份调度表只会抄得更差、更容易过期——到达的实测计数在 Trace/Messages，占用率与槽时长在 Bus Statistics，逐帧的解码在 Messages 展开行。**发送者只认结构化的绑定**：ARXML 里 ECU → `I-SIGNAL-I-PDU-GROUP` 引用 → 组自己的 `COMMUNICATION-DIRECTION = OUT` → 组里的 PDU → 载这个 PDU 的帧，所以"BLU 收 BackLightInfo、BSC 发它"这种反向绑定不会把接收方印成发送方（`_Tx`/`_Rx` 那种**名字约定一律不作数**）；自带的这份 ARXML 里 48 帧有 12 帧能解出发送方，其余确实没被绑定（FIBEX 集群导出根本不带 ECU↔PDU 引用，所以那一路永远是"没说"）。
- 这一节**不是调度表、也不是角色入口**：FlexRay 节点没有角色可切（角色是 DBC 节点的概念），但 **ECU 叶可以点**——选中即在该 ECU 的详情里编辑它作为发送方的那些槽（见《交互式生成器》的 FlexRay 条）。左侧详情面板在只有 FlexRay、没有 DBC 节点时会指向这棵树，而不是说"没有节点可显示"。
- **Profile 行**：窗口顶部一行管全部——下拉枚举工程目录 `profiles/*.toml`，**应用**一次性下发角色覆盖与硬件映射（all-or-nothing：任一总线/节点/角色词错配则整份拒绝，原因进状态行）；**编辑**用系统默认编辑器打开选中的 .toml；**删除**点两次确认后删文件。右侧输入名字后点**存当前**，把现在的角色与硬件挂接快照写成新 profile（`[[node]]` 只记模拟节点，`[[hw]]` 带驱动字与通道号）。`[[hw]]` 全量声明——未列出的总线解挂。语义与 CLI `--profile` 完全一致——同一套工程在 simulation / bench 之间零修改切换。

## 硬件联动（Kvaser / Vector）

- **挂接**：Buses 窗口每行的"硬件"列——下拉列出本机可用通道，跨两个驱动：**Kvaser**（canlib32.dll）与 **Vector**（vxlapi64.dll，运行时加载，驱动未装则该驱动不出现条目），条目前缀 `[K]` / `[V]` 标明驱动，选中即挂接（Kvaser 波特率仅支持 10/50/62/83/100/125/250/500/1000 kbit/s 标准值；Vector 以 bit/s 直接下发）。解挂随时可做。
- **总线模式（Simulated / Real bus）**：工具栏 Simulation 旁的开关，也是模拟流量上不上线的**唯一开关**。Simulated（默认）下硬件**挂接保留但不收不发**——Buses 行标注"已下线"；切到 Real bus 即上线：RX 进总线，工具为"模拟"节点发出的**一切流量**（生成器条目、脚本 `send`、触发反应帧）出线，无需重新挂接。纯仿真与真实总线通信由此一个开关分开——想只听不发，把所有节点角色留在"离线"即可。状态栏 `MEASURING (…)` 的括号说的是**帧去哪儿**，用词与此一致：`simulation`（一条硬件都没挂）、`real bus · N`（N 条总线在线）、`simulation · hardware parked`（挂了但开关在 Simulated）。
- **CAN FD**：Kvaser 挂接时按该总线的 FD 数据段波特率申请 FD 能力（预设 500k/1M/2M/4M/8M 与 80%/60% 采样点；无预设匹配或硬件不支持时**降级为经典模式**并在状态行如实标注）。Real bus 下 FD 帧发车带 FDF/BRS 标志；收到的 FD 帧的 FD/BRS/ESI 徽标照常解码。挂接状态行与 Buses 行都会显示 FD 态。Vector 首版仅经典 CAN（FD 参数接口后续迭代提供）。
- **接收**：挂接后（Real bus 模式），适配器收到的一切帧照常进总线——聚合、Trace、负载、规格、触发全部可见。**真实节点就这样进入工具**：把它的角色留在"离线"（我们不冒充它发车），它的真实流量照常显示。
- **只收降级**：挂接优先申请收发（init access）；通道被其他程序（如 CAN King）占用时自动降级为**只收**模式并在状态行与 Buses 窗口标注。虚拟通道的只收句柄仍可发车；物理适配器的只收句柄写入会失败（帧仍进内部总线，视图不丢）。**发车被线路拒绝不再是静默的**：第一次进 Write 窗口（带驱动自己给的原因），同一条之后只累计次数，Buses 行标红 `发车被拒 ×N`（悬停读第一次的原因）——线没接、没端接、对端没人，从此看得出来。
- **与其他工具共存**：驱动的仲裁是通道级的——本工具挂接期间（哪怕只收模式），CAN King 等需要初始化访问的程序可能无法启动同一通道；反过来它们占住通道时，本工具自动降级只收。想切换工具，先在本工具"解挂"再让对方上。
- 挂接的持久化路径是 Profile 的 `[[hw]]`（见命令行与 Network 节）；GUI 手动挂接仍是会话状态。
- **FlexRay 只收监听 + 集群描述**：Buses 窗口的 FlexRay 区**是上面 CAN 那张表的同构版**——一路一行、同样的列序与列宽（Name / 描述 / 速率 / 硬件 / 移除），标题行也是同样的两句：**`+ Add FlexRay` + `N 路`**。加一条 FlexRay 路 = 挑一份集群描述（FlexRay **正在回放的日志里真有其流量**的路；最后这一种行在名字下面那行灰字里带上"日志里有这路流量"，它值得占一行：那批帧没有集群描述就一直解不出名字，而 `Open...` 就在它自己那一行上。Name 列**可以改名**（与 CAN 行同一个原生 InputText、同一套"编辑完即下发"的行为）：**名字只是给人看的**，框下面那行灰字 `#n` 才是这路的 cluster 个帧），所以按槽统计会让帧名每来一帧变一次、周期也不是任何一帧的；解析不出帧的到达（这一路没描述、或描述里没有这一帧）自成一"无名"行，不会与有名行混在一起。展开出来的信号行**信号名在第 1 列（Message）、值在第 2 列（Bus）**，值向右延伸经过后面的空列（Bus 列设了**列级** `NO_CLIP`：imgui 只因此不把该列的绘制通道裁到列宽，表格自身的裁剪仍在，所以既不会被列边框切断也不会滚出表外；表级 `NO_CLIP` 是另一回事，该表冻结表头时会让后面的列消失，不要使用）。名字超过 Message 列宽会**截断在列边**（不再和值重叠），要看全就拖宽该列。值形如 `2.54 Mpa (正常)  (1Fh)`，缺的单位/类型/标签不打印占位符；解释该行为空的说明放在值那一格。**Statistics 窗口**把 FR 槽位与 CAN 报文并列：计数、观测到的帧间隔 min/avg/max、载荷长度、占比（抖动只在 Messages 那侧给）。窗口过滤器口径：把窗口限定到某个 CAN 通道时 FR 行不出（那是 CAN 侧的编号，FlexRay 要用 `FlexRay: <路名>` 那一档），方向与帧类型同理（FR 行没有这两件事可比）；**信号值条件（`Name>10`）两边都算**——CAN 行问 DBC，FR 行问这一帧在自己的集群描述里解码出的物理值（与曲线、展开子行同一个数），名字这一帧没有、或这一路没挂描述，该行不出（与 CAN 侧"解不出就不解释"同一条规则）；文本过滤匹配 FR 帧名与槽号，载荷与时间范围照旧。**"仅 DBC" 是逐行问"有没有数据库说明这一条到达"**：CAN 行问的是 DBC 里有没有这个报文，FR 行问的是**该路集群描述在这一相位排不排这一帧**——所以挂着描述的正常帧在勾选后**留在表里**（以前整条 FlexRay 一起消失，把这个勾选要保留的行也滤掉了），而"这一路没挂描述"与"挂了但这一相位未调度该帧"两种行都会被滤掉（Messages 展开行的说明会分别指出是哪一种）。**作用域下拉另有 `FlexRay: <路名>` 一档**（未改名时那个名字就是 `FR{n}`；与 `Bus: CAN{n}` 分列，因为 cluster 索引和 CAN 通道索引是两套编号）：选中它该窗口只显示这一路的行，CAN 行一并出去，Statistics 的占比也变成这一路自己的占比——两路 cluster 混在一张表里时这是唯一能把它们分开的办法（没有名字的帧无法用文本过滤筛出）。可选项来自"已配置的路 ∪ 当前有流量的路"，所以纯回放、一份描述都不加载也能只挑一路。整路删除（行末 `x`）时指向它的作用域自动退回 All buses；只 `解挂` 不动作用域、也不动描述（这一路还在，只是暂时不收）。**"Manual" 手选集合现在也包含 FlexRay 槽**：作用域下拉选 Manual、按 `…` 打开的 Message Selection 里，CAN 报文清单下面多一段 **FlexRay** 清单（每行一路的一个槽：`<路名> slot N  帧名`（未改名时路名就是 `FR{n}`），同槽按周期相位排着的几帧并列写在行上，因为窗口筛选的单位就是槽），勾中的槽与勾中的 CAN 报文一起构成这个窗口的白名单——Trace/Messages/Statistics 的显示与这两个窗口的 CSV 导出都使用这一份，不必再按整条总线或整路切换。**"Select all matching"** 两边都纳入（查询命中帧名的槽一并进白名单）。两类条目各存各的（工程文件里 `manual` 只写 CAN id、`fr_manual` 只写 `(bus, slot)`，所以旧工程照读、新工程在旧版本里只是丢掉 FlexRay 那半），删除 CAN 通道时只重编号 CAN 那一半，槽号不受影响（FlexRay 的 bus 索引是配置的顺序，与 CAN 通道号无关）。工具栏的**录制白名单**同样认两种编号（CAN id 与 `FR<路>:<槽>`，见《回放与录制》），回放块的 id 过滤仍是 CAN id 列表（回放块本身是 CAN 通道实体）。**Messages 与 Statistics 的 CSV 导出都含 FR 行**（`bus` 列写这一路的名字，默认即 `FR{n}`；`id` 列写槽号）。
- **FlexRay 的录与放是对称的**：CANoe 录的 **BLF**（FR_RCVMESSAGE / EX 对象）与 **ASC**（`Fr RMSG` 行）里的收帧一并解出进上述视图；本工具**自己录的文件**（`.blf` 或 `.asc`）也写同类对象/行，自家 ASC 的 FR 行按"两个字节计数"定位载荷，**有无帧名都读得回**、`base hex` 与 `base dec` 都按声明进制解，所以录完再放回来是同一批帧。FlexRay 帧计入帧数与 f/s；`--convert` 与 Trace 的 ASC 导出都保留 FR 行（导出的 ASC 按时间升序混排两种总线）。回放按时间戳顺序调度，**不提供进度条随机跳转**（CANoe 的录制模式同样如此）；as-fast-as-possible 模式下可前进到日志末尾。
- FlexRay **信号可以订阅并画曲线/数值**：信号选择树的 FlexRay 分组按 cluster 列出各路的槽与信号（`(总线索引, 槽, 信号名)` 就是它的身份，与曲线、触发条件同一三元组）。容量与 CAN Trace 共用上限；**负载与规格监视另有自己的口径**（见"总线统计与规格监视"节：占用率按**静态段描述参数算的时间占用率**，规格按声明周期逐帧判）。总线模式为 Simulated 时监听同样"已下线"（保留配置不收帧）。

## 触发器（Triggers 窗口）

- **条件**：信号越阈（沿触发，电平跟随该报文自身的帧，帧类与报文类一致才匹配）、ID 出现（一次运行锁存一次）、错误帧（同上锁存）、周期超时（复用规格监视的宽限判定——触发器与规格的 Dropped 判定永不打架，报文恢复后电平清除，每次掉线都是新沿）、**FlexRay 帧到达**（按 cluster + 槽，出现类同样一次运行锁存）、**FlexRay 信号越阈**（身份就是 `(总线索引, 槽, 信号名)`——与曲线同一个三元组；电平跟随该路描述解出的物理值，解不出的一帧不动电平）。
- **动作**：开始录制 / 停止录制 / 发送发生器条目（反应帧带触发帧的同名信号镜像，网关式转发）/ 插入标记（Graphics 画竖线）/ 清空 Trace（不影响聚合、规格与录制）。
- **触发启动的录制**自动带**预触发上下文**：文件以事件前 256 帧开头；**触发停止的录制**在边沿后再滚 32 帧（含边沿帧）才闭文件。手动录制不受影响，立即开始/停止。
- 触发求值先于一切帧处理，触发帧本身被录进文件。触发器内容随工程保存；运行态电平与计数不落盘。
- **锁存与重置**：ID 出现/错误帧条件每运行锁存一次。Triggers 窗口的 **Re-arm latched** 按钮手动重置锁存（下一个对应事件再次触发）；**清空 Trace 动作**触发时也会同时重置所有出现类条件的锁存——"清一次、等下次"。信号越阈与周期超时的电平是真实电平，永不受重置影响。

## Graphics（曲线窗口）

- **两条游标 A/B**（工具栏 **Cursors**）：**双击图面**放下一个（先 A 后 B；两条都在了，双击移动的是**离得远**的那条，近的那条用拖的），**按住游标线拖动**微调——按住线上拖动时平移让位，一个手势只动一样东西；而且**这一下按住归那条线**：指针划得比刷新率快也不会松手、不会半路变成平移（要放手再按别处才换目标）。右上角读数块给出 `A`/`B` 两个时刻与 **Δt**（µs/ms/s 自动换单位，B 在 A 前面就读负数），下面每条曲线一行 `名字 A值 → B值 Δ差值`。
- 游标记的是**时间**，不是屏幕位置：平移、缩放、实时推进都会让线跟着视图走，而它标的点不动；跑到视野外的游标**不画线**（时刻仍留在读数块里，那才是读数的地方）。没打上的那条印 `-`，没有样本的时刻也印 `-`——**不拿 0 冒充一个读数**。
- 游标位置是会话状态，**不随工程保存**（它指的是采样环上的位置，新一轮测量一清，那个时刻就没人站着了）；**Cursors** 开关本身照旧保存。

## State Tracker

- 对订阅信号的历史做**状态分段**渲染：值不变的最长区段为一条带，带内标值。
- **快速加入**：Graphics / Data 窗口左侧信号列表里**右键任一信号** → 选目标 State Tracker（或"+ 新建"）即加入跟踪，无需经过信号选择弹窗。
- 恒定贴实时边缘（回放中跟随 playhead）；时间窗宽提供 5 秒到 30 分钟的预设。
- **最小显示时长**：窗口头部 "Min ms" 输入毫秒数——更短的碎带自动并入前一段（第一段并入后一段），抖动信号保持可读；0 = 全部显示。随工程保存。
- **默认模式**：状态列表取 VAL_ 值表（显示枚举标签而非数字）或已观测数值；每个状态可钉颜色（色块 → 取色器），未钉的按会话槽位自动配色（同一值在会话内颜色稳定，超出调色板的新值哈希入位可能撞色，繁忙模拟量整体回退素色带）。
- **自定义模式**：按切分点把值轴分成区间，每区间自定义名字与颜色，规则**接管**标签与配色；删切点合并区间。
- 可见状态只有 {0,1} 时自动画成**二进制方波**（无需配置）。取色器三段式：自动 + 12 个低饱和默认色 + 完整调色板。
- **Export CSV**：导出当前窗口的状态区段表——每个可见信号一行区段（总线、信号、起止秒、时长、标签），与屏幕所画一致。无区段时提示且不写文件。
- 颜色钉住（overrides）与自定义规则随工程保存；自动槽位配色是会话状态，不落盘。

## Monitor（轻量监控面板）

- **View > Monitor**：纯文本行的大屏面板——一行一个信号：`[状态点] 标签 值 单位`，从信号选择器挑行（数据库信号 / 派生信号 / 系统变量通吃，与 Data/Graphics 同一选择树）。
- **着色规则**：每行可开一条阈值规则（`>=` 或 `<=` 阈值时整行换成所选调色板色），行内直接改阈值、点按钮切方向、点色号循环换色——"温度超 90 变红"这类一眼可见的告警零配置。
- 行随工程保存（键、标签、小数位、规则全部落盘）；Clear 清空全部行；单行 `x` 删除。

## 系统变量（System Variables 窗口）

- **View > System Variables**：CANoe 式的命名空间变量管理。表格列出 namespace、name、实时 Value（**行内可改**）、Init、Min、Max、Unit/Comment；"+ Variable" 或行内 edit 打开编辑对话框（非法输入在对话框内直接报错，不落总线），x 删除。定义随工程保存。
- **脚本访问**：`sys_get("ns::name")` 读、`sys_set("ns::name", v)` 写，或用 CANoe 风格速记 `@sysvar::ns::name`（读）/ `@sysvar::ns::name = v;`（写，仍受界限钳位）。信号速记 `$报文名::信号名` 同样可用（等价 `sig(id, "名字")`，id 由库名字解析，名字拼错在启动检查报出）。写入被夹到定义的界限内；引用未定义的变量在节点启动时报出来。
- **可观测**：每个变量发布为一条合成订阅流，信号选择树里**按 namespace 分组**——Data / Graphics / State Tracker 像选数据库信号一样选用。
- **测量开始复位**：每次 Start（虚拟或回放）所有变量回到声明的初值并重发布，观察曲线不会拖到上一次运行的尾巴。
- 值为数值型（浮点/整数通用）；改名 = 删除旧名 + 定义新名（脚本引用不会自动跟随，启动检查会报出来）。

## Write 窗口

- **View > Write**：整系统一条的滚动输出面板——节点 `print`（带 `[节点名]` 归属）、装配层 `[check]`/`[info]`、定时器与系统变量告警、节点熔断错误（红色），以及命令状态（测量启动/停止、DBC 装载、硬件挂接等，蓝色 info）。
- 每行带总线时钟戳 `[秒]`；窗口在底部时自动跟随新行，向上滚动阅读时不被拽回。顶部按类别过滤（脚本 / 信息 / 告警 / 错误）。
- **导出**把当前过滤视图写成文本文件（`[HH:MM:SS.mmm] 文本`，与窗口显示同形）——"所见即所存"；全部类别都过滤掉时拒绝导出而不写空文件。
- **清空**只清 Write 窗口自身——节点日志、测量、录制均不受影响。过滤器是会话状态，不随工程保存。
- **底部状态栏只留最后一条，这里才是记录**：除了上面那些类别，步进过程中冒出来的消息（回放跑到末尾、触发器命中、post-roll 结束）与前端自己的失败（工程读不到/解析不了、导出失败、日志打不开、集群描述装载失败）都会同步落进 Write 窗口。状态栏一行几毫秒就被下一次动作冲掉，而这些消息往往是要回头再看一眼、要贴进反馈里的。
- **打开缺文件的项目**：状态栏只说 `project loaded · N 项未能载入（Write 窗口有明细）`——哪个文件不见了、解析器怎么报的，逐条在 Write 窗口里（红色 error）。载入不是全有或全无：能恢复的部分照常恢复，缺的那部分如实报出来，而不是被"loaded"那一行盖掉。

## 总线统计与规格监视（口径说明）

- **Busload** 按线上一帧占时计算：经典帧 `47+8·len` 位、扩展帧 `67+8·len` 位，FD 的载荷与 CRC 走数据段速率；位数为无填充近似。统计窗口 1 s 滚动更新，**窗口只由新帧推进**——总线静默时读数冻结，不归零。
- **FlexRay 的"静态段占用"是同一类数字，但单位是槽不是长度**：一帧占用的介质时间 = 该路描述里的 `gstaticSlot × gmacrotick`（载荷 24 字节还是 254 字节都一样），占用率 = 窗口内到达帧的占用之和 / 窗口时长。两点边界：①**动态段不计入**（被动监听只报静态槽，算 minislot 需要参数里没有的 action point 索引）；②没有挂描述、或描述里没声明槽时长时**只数帧、不报占用率**（该行显示 `-`，不是凭空的 0 %）。冗余集群里一帧是一条记录（日志的 channel mask 写"both"），不会双算。
- 错误帧单独计数并计入占时；硬件寄存器行（TEC/REC 等）在仿真模式下无意义，不列。
- **Messages / Statistics 的 Clear** 清的是逐报文计数（两窗同源，**FlexRay 的帧计数一起清**——它们如今同表并列，只清 CAN 会让按钮对一半表格说谎）——测量照常进行，新帧到达即重新计起；总线负载与规格记忆不受影响。过滤器设置不随 Clear 重置。
- **规格监视**用逐步区间判定周期（不是运行平均，也不受单帧毛刺影响）；Export 导出的 CSV 头部带判定前提（每总线数据库路径、容差、宽限、声明周期数），正文含全部锁存违规（不受窗口过滤勾选影响）。同一报文持续违规只加深计数，不重复开行。
- **FlexRay 走同一套判据，前提换成调度表**：描述声明了每帧占哪个槽、哪个周期相位、重复几次、载荷多长，于是四条都对得上——**Unknown**＝到达的槽/相位在这路描述里排不出帧（就是 Messages 里那条"无名"行）、**Dlc**＝实到载荷**短于**声明长度（长于不算违规：FlexRay 槽的载荷是定长的，日志把整槽记下来时帧名之外的填充不是错）、**Cycle**＝实测间隔偏离 `cycle_repetition × 宏周期` 超过容差、**Missing**＝原本在到的帧静默超过宽限。报告行与 CSV 的 bus 列写这一路的名字（默认 `FR{n}`）、id 列写 `slot N`、name 列写帧名（解不出的写 `not in the schedule`）。CAN 与 FlexRay 的存储是**两张表**：通道号与 cluster 号是两套编号，`(0,5)` 既是 CAN0 的 id 5 也是 FR0 的槽 5，合成一张表就会互相定罪。
- 扩展帧在规格表与 CSV 的 id 列带 `ext` 后缀。

## 回放与录制

- **离线扫描（Scan）**：Replay 模式加载日志后，工具栏 **Scan** 按钮一次性把整份日志灌进聚合 / 统计 / 负载历史 / 规格 / Trace——**不用回放即可浏览全量结果**（"1 GB BLF 秒开"路线）。扫描无回放时钟、无触发动作、无节点分发、不录制；扫完自动停靠，Play 照常从头重放并重新计数（不会与扫描结果双算）。重扫从零重测。
- 回放中发生器照常可注入（日志时基为主：帧间仿真钟冻结，注入落在日志轴上；日志静默段注入随之冻结）。回放期间录制本就关闭，注入帧不落盘。
- 录制后端随扩展名：`.asc` 写 ASC（经典/FD/错误/远程帧），`.blf` 写 Vector 二进制容器（经典/FD/远程帧与错误帧，错误帧写为 `CAN_ERROR_EXT` 对象）。触发启动的录制带预触发上下文与 post-roll（见触发器节）。BLF 只读的日子结束了。**录制位置**：工具栏 Record to 输入框只填**文件名**（默认 `record`，自动加日期后缀），保存在打开工程的 `Record/` 文件夹下；填**绝对路径**则按它保存；未打开工程时落到程序工作目录。状态行在开录时显示完整落盘路径。
- **BLF→ASC 转存**：`--convert <in.log> <out.asc>`——纯流式转码，不经总线与时钟，帧的时间戳/帧类/载荷原样保留。
- **预触发 / post-roll / 标记上限**：Triggers 窗口顶部可调（默认 256 / 32 / 512），随工程保存。
- **录制过滤**：工具栏录制行旁的过滤框同时认两套编号——CAN 写 hex id 列表（如 `100, 3F4x`，`x` 为扩展帧），**FlexRay 写 `FR<路>:<槽>`**（如 `FR0:13`，路号就是 Buses 表里那行行末的 `#n`——**改了名也照旧用编号写**，这里没有地方认名字；十进制，与调度表和 Trace 的 `slot 13` 同一写法）。文件里只落这些条目（预触发上下文与 post-roll 计数同步按过滤口径）。**前缀不是装饰**：`13` 既是 CAN id 也是槽号，所以不带 `FR` 的数字永远不会被当成槽；反过来只写槽也不会把 CAN 一侧静音——这个框列的是"要留什么"，不是"关掉哪条总线"（两半各自判：`admits_can` / `admits_fr`）。过滤器**只管文件**：Trace、统计、负载与规格始终看全总线。留空 = 全部录制。错误帧没有 id，过滤开启时不会落文件。
- **Trace 虚拟滚动**：行缓存 + 按可视区渲染——200k 行的过滤结果也能流畅滚动/排序（内存约 18 MB 封顶；超出部分按最新优先截断并在数量上如实显示）。缓存**只补新行**：过滤器没动、没点列头排序、该路的集群描述没换、环也没被清空时，一次刷新只走"上次建缓存之后到的那几帧"（实测 50 000 行的 FlexRay 环上，从每次 7 ms / 勾选"FR 信号"时 70 ms 降到 1.4 µs / 2.0 µs）；改了过滤器或点了列头排序会重走整条环一次（FlexRay 展开时那一跳约 8 ms，与不展开的 6 ms 同一档），清空 Trace 同样触发重建。缓存比环多留的历史不会因为环溢出而立刻从画面上消失（最多留到 200k 行上限）。**上限按帧行计**：勾"FR 信号"不占用额度（解码子行不是缓存条目，父行只带一个子行计数），所以展开视图与不展开视图看得见同样多的历史帧——以前展开时子行也计入 200k，等于少看得见约八成。
- **Trace 过滤**：窗口顶部一排滤网——总线范围 / 方向 / DBC only / **payload 字节搜索**（hex 对、空格可选，如 `11 22 3F`，匹配含此序列的帧；无法解析时不过滤）/ **帧类型**（Any / Data / FD / RTR / Error）/ id 与报文名子串 / **时间范围**（`从 s`、`到 s` 两个秒数框，留空 = 该侧不限）。过滤器只管这个窗口的显示，Trace、统计、规格仍看全总线。
- **收起的那一行筛选不会偷偷生效**：payload / 帧类型 / DBC / 时间范围 挤在 **`筛选`** 按钮后面的可折叠行里，行收起时控件看不见、条件照旧在滤——所以按钮上写 **`筛选 ·N`**（N = 此刻真在生效的条件数），悬停一行点名是哪几项（`payload · 帧类型 · 仅 DBC · 时间范围`）。只算**真的在过滤的**：填了但解析不出来的文本（payload 写 `zz`、时间框写 `abc`）不算，帧类型停在 Any、时间框留空也不算。**行右键菜单的 "Clear filter" 一次抬走全部条件**（文本、payload、帧类型、仅 DBC、时间范围、方向、作用域回 All），两种总线同一个动作同一个口径；**唯独不动这个窗口的 Manual 手选集合**——那是用户一条条勾出来的名单，不是一时输入的过滤式，一键清除不该悄悄吃掉它。
- **表里的两条游标 A/B**：**行右键** → **Set cursor A** / **Set cursor B** 把游标落在这一行的时刻（CAN 与 FlexRay 行都放，一次右键只动一条），被标出的行带底色（A 琥珀、B 青蓝——与 Graphics 那对游标同两色），表头紧接着读出 `A 1.234567s  B 1.456000s  Δt +221.433 ms`（时刻给到微秒：行与行就差微秒）。再设一次就是移动它；**Clear cursors** 只在有东西可清时才出现。与曲线窗口共用同一句读法，只有放置手势不同（图上是双击 + 拖线，表里是右键选行——表格没有可拖的线）。游标是会话状态，**不随工程保存**：它指的是行环里的位置，新一轮测量一清，那个时刻就没人站着了。
- **信号值条件两种总线都算**：框里写 `Name>10`（运算符 `> >= < <= == != =`）时，CAN 行按它的 DBC 解码比较，**FlexRay 行按这一帧在自己的集群描述里解码出的物理值比较**——与曲线上画的、展开子行里印的是同一个数，所以不会出现"过滤留下它、图上看着不对"。这一帧没有这个信号、或这一路根本没挂描述，该行不出（过滤器不替解不开的行走后门）。多个条件是"且"。
- **点一行就是"这一行"**：左键点任一行，该行底色变亮蓝。"哪一行"按**时刻 + 哪条总线/哪一路 + 地址（CAN id 或槽号）**认定——仿真里一步之内的所有帧盖的是同一个微秒，只按时刻点亮会把那一步的几条一起染上（第一版就是这样，真机上一看：61.820000 的 CAN1 id 100 与 200 同时亮了，按一次 ↓ 也跳了两行）。底色用的是表格**交替底色**那一格，而错误行/远程帧与游标 A/B 的底色走另一格，所以同一行可以同时是"选中的"和"被标记的/报错的"，两件事都看得见。有选中时表头多一句 `已选中一行 · ↑/↓ 换行 · Ctrl+C 复制该行`（没选中就不写，免得报一个不在的状态）。↑/↓ 按**屏幕上的行序**走（表里新行在上，所以 ↓ 是往旧的方向走），**一个展开的 FlexRay 帧算一步**：它的信号子行属于这一帧，一起亮、一起跳过；上下到底就停在这儿，不会把选中清掉。选中的行若因过滤、清空或环被裁而不在了，下一次按键从**当前最新的一行**重新落地——键盘不该走进死路。Ctrl+C 复制选中的那一行，**八列与表格一致**（FlexRay 行也补上了 "Copy row"：同一个动作在两处用了两个词会被读成两件事）。两个键只在**指针停在本窗口且没有输入框在打字**时接管——过滤框里的方向键与复制仍是它自己的。选中是会话状态，不随工程保存，理由与游标一样：它指的是行环里的一个位置，新一轮测量一清就没人站在那儿了。
- **过滤框里的精确地址**：普通文本是**子串**搜索（好打，但 `13` 同时命中槽 113、槽 130 和任何名字里带 13 的帧）。要"只要这一个地址、别的全出去"就写前缀：**`id:1AB`**（CAN，标准帧）、**`id:1ABCDEFx`**（29 位扩展帧，`x` 与 ID 列、录制过滤同一写法）、**`slot:13`**（FlexRay 槽，十进制，与调度表/Trace 的 `slot 13` 同写法）。用冒号不用等号：`Name=3` 已经是信号值条件，而 DBC 里真有一个信号叫 `Slot` 或者 `ID`。两套编号不互解——`id:13` 不出 FlexRay 行，`slot:13` 也不出 CAN 行。行右键菜单的 **"Filter this ID"** 写的就是精确形式（带着帧类别），所以点完留下的就是那一行。**打一半的地址不猜**：`id:` 后面不是 hex、`slot:` 后面不是 0–65535 的十进制数时，整串仍旧按**普通子串**处理（表里通常就空了——框里显示的正是你打的字，改一个字符即恢复），不会被当成"地址写错了但大概想要 13"。时间范围两个框、"过滤行"是否展开、FR 信号子行是否展开，都随工程保存（旧工程无这些键即读为空）。
- **Trace 容量与归档**：Measurement Setup 顶部的容量下拉（50k–2M 帧，随工程保存）。超出容量时最旧的帧**写入临时归档文件**（不丢失）——Trace 窗口顶部琥珀字提示"已归档 N 帧"；**Export Trace 会先回放归档再写热环**，导出的 ASC 覆盖整段运行。归档文件在系统临时目录，新运行自动清空。
- **Trace 的 Clear** 清空显示与归档——测量照常进行：录制不动、逐报文计数不动，清完新到的帧照常上屏。过滤器设置不随 Clear 重置。
- 回放支持倍速增减/直选与 **as-fast-as-possible**（一趟把整份日志抽干，用于向后赶）；进度条只跟随不回跳，**不提供时间轴随机跳转**（CANoe 的录制模式同样如此，理由见上面 FlexRay 一节）；暂停/恢复的边沿不产生重复帧。

## 工程与兼容性

- 工程（`.rxproj`）单文件 JSON，DBC 路径相对工程目录；30 秒自动保存。
- 旧版本工程在新版本照常加载：新增字段全部带缺省（如信号/触发器的帧类位缺省为标准帧）；未知的功能码只丢弃对应条目，不影响其余配置。
- 新版本保存的工程可能包含旧版本不认识的字段/码：旧版本读新工程时对应能力缺失但程序可用（波形状等按"丢源不丢条"约定处理）。
- 坏库容错：复用报文（mux）条件引用了消息里不存在的开关时按"无条件"放行——显示数据而不是空解码；`VAL_TABLE_` 命名表引用暂不可解析（解析器限制，有测试钉住）。
- 信号类型标记（`[u16]` / `[f32]`）按 `SIG_VALTYPE_` 声明解码位模式；can-dbc 的 0/1/2 码与 Vector 文档约定不同，以解析器为准。
