# 架构文档

roxy-can 的结构、关键决策与不变式。用法见 `README.md` 与 `docs/usage.md`，取舍理由见 `docs/roadmap.md`，还没做的事见 `TODO.md`。

## 总体分层：核心线程 + 命令/快照边界

```
前端（UI 线程，60 fps 渲染）
   │  写：BusCommand → mpsc 收件箱（单入口）
   │  读：Snapshot ← Arc 信箱（try_lock，拿不到沿用上一帧，永不阻塞）
   ▼
BusCore（bus-core 线程，事件驱动）
   信道/DBC · 仿真时钟 · 发生器 · 帧源 · trace 环 · 聚合
   订阅与采样缓存 · 规格/触发器 · 录制器 · 回放 · 硬件端口
```

- **归属划分**：核心拥有全部总线状态与执行；Web 前端拥有面板布局、弹窗与草稿态（数字/源码/路径的未提交草稿）、文字节流、状态行文案。边界记录在 `BusCommand`（事件）与一组原子旋钮（步长/容差/宽限等连续量，前端每帧写、核心每轮读）。
- **双驱动**：产品用线程驱动，测试与 CLI 用手摇驱动（命令同步执行、时钟手动推进），所以全链都能在 `cargo test` 里跑。核心对前端的隐式直读在线程驱动下当场 panic——前端对总线的每一条读写都必须"读经快照、写经命令"。
- **纪律**：每步结束代码可编译、测试全部通过、程序可用、可发版；重构期间冻结新功能。

## 核心时钟模型：事件驱动，不用固定步长

信号值全是时间的解析纯函数（任意时刻直接求值，无需积分），固定网格只有代价没有收益。事件只有两类：发生器条目的周期 TX 槽位、外来帧（回放日志顺序到达 / 硬件到达）。核心睡到最近的截止时间（并设一个短超时以保证命令仍被接收），醒来排空→推进到当前时刻→有变化就发布快照（至多约 60 次/秒）；空闲即休眠。

- **时间戳永不量化**：槽位保留精确微秒，值在槽位时刻求值。核心超跑（醒来晚了）按原始时间戳顺序补发——正确的数据晚到，好过准时的失真数据。
- **暂停不停车**：只翻标志、重算截止时间。
- **唤醒精度**：Windows 默认定时器粒度不可用，需要把系统时钟分辨率拉到 1 ms；对 ≥10 ms 周期，±1 ms 抖动可接受。

## 数据共享：共享分块 + 写时复制

快照每秒最多发布约 60 次，历史数据的发布代价曾是瓶颈，所以订阅采样缓存与 trace 环都是"封存分块（只读共享，引用计数）+ 活跃尾部"的结构：克隆只是块引用计数加一条尾部拷贝，写侧改动走写时复制，不会影响 UI 持有的块。直播采样走增量追加，回填才走全量展平。

trace 超过容量时**不丢弃**最旧的帧，而是追加写入临时归档文件；导出先回放归档再写热环，所以导出的日志覆盖整段运行。归档创建失败就降级为纯裁剪，并在界面上如实提示。

## 两套编号空间，永远不要合并

CAN 的地址是 `(通道, id, 帧类)`，FlexRay 的地址是 `(路/cluster, 槽)`。两个空间各自编号，`(0,5)` 既是 CAN0 的 id 5 也是 FR0 的槽 5，所以**任何把两者拼成一张表的键都必须带协议标签**：聚合、规格、订阅信号键、触发条件、录制过滤、手动勾选的集合都是枚举化的键，而不是共享的数字。

一条相关的身份规则：**cluster 索引是身份，不是列表位置**。BLF 按帧里的 cluster 编号归属、脚本里写的是 `fr_sig(1, …)`、录制过滤里写的是 `FR1:5`，所以删除一路绝不重编号其余各路；空出来的号交给下一次添加。

## 仿真节点

- **常驻核心**：`ScriptNode` 常驻核心，绑定一条信道。测量启动时从源码重编译：主块初始化全局 → `on start` → 周期定时器惰性武装。帧的分发发生在步循环里；脚本产出的发送条目由核心成帧压进同一批处理，与触发器的 Send 同机制，因此节点会收到自己发的帧。
- **防失控**：每回调有指令预算与递归深度上限；出错的节点自动停止运行（日志留痕），重新 Apply 或重启测量恢复。`print` 走节点日志环经快照发布。
- **外部调用解析链**：内建表（编译期解析，无动态派发）→ 进程内注册表（外部仿真元件）→ 节点私有钩子。未认领的名字落运行时错误，字节码格式不因任何一条缝改变。
- **定时器**：周期定时器（错过收敛为一次触发加重同步）+ 命名一次性定时器（任意回调可武装、触发即失效）。控制操作在回调结束后排空应用，在非定时器回调里改周期记告警。

## 描述文件读取

DBC 与 ARXML 都只读：解析出的事实先进统一模型（`Cluster → Network → Frame → PDU → Signal`），DBC/FIBEX 由适配器转成同一模型，`SymbolTable` / `FrDb` / 以太网矩阵只保留文件解析、发送元数据与 UI 表格；旧解码/编码方法已仅测试可见。核心按 `DecodePlan`/`PlanCache` 解码与编码；ARXML 文档里的 mux、container、linear transformation 直接进计划。编辑与写回不在这条路径上。需要补解析时参考同目录的 roxy-arxml / roxy-dbc，但只移植读取侧事实（元数据、布局、约束），不搬序列化/往返保真代码。

- **DBC**：`CM_` 报文/信号注释、`VFrameFormat`（DLC ≤ 8 的 CAN FD 帧）、`SIG_VALTYPE_`、`SG_MUL_VAL_`、周期属性都进目录；注释与帧类在 DBC explorer 的悬停/标签里显示。
- **ARXML**：CAN 的 `SW-BASE-TYPE/BASE-TYPE-ENCODING`（`2C`、`IEEE754`）决定符号与浮点，类型名只作缺省回退；FlexRay 的 `COMPU-METHOD` 限值按 factor/offset 换算成物理量程（负 factor 交换上下界），没有可用范围时目录保持 0..0，写 Setpoint 按不夹取处理。
- **范围的下游**：目录量程同时驱动图表/Data 的刻度和 Setpoint 的夹取；未声明范围的信号不再被误夹成 0。

## 帧键：标准/扩展分家

同数值的标准帧与扩展帧是**两个不同的报文**：DBC 表、聚合与规格按帧类位区分；订阅键以集群 id + 帧类 + 名字为身份，总线路号只在路由时由集群解析。脚本与生成器按"id ≤ 0x7FF 标准、> 0x7FF 扩展"划类，`send`、`on message`、信号编解码同一规则；裸 id 场景（显示与名称回退查找）标准优先、回退到扩展帧。已知妥协记在 `TODO.md`。

## 角色模型：数据来源、角色、驱动三分离

"DBC 节点 ≠ 仿真节点"的不一致在模型层面消灭——三个正交概念各有一个事实来源：

- **总线拓扑**：唯一数据来源是 DBC（FlexRay 侧则是集群描述）。节点名单、报文与信号、发送关系全部从文件推断，程序绝不重复声明。
- **执行角色**：两态声明，只能命名库里已有的节点——**模拟**（本工具以它名义发送）/ **离线**（不模拟；真实节点的流量经 Real bus 模式下已连接的通道进来，或来自回放块）。**缺省即离线**，restbus 无需配置，存档里只记对缺省的偏离。切入模拟为节点补建发生器条目；退出只停发——条目、载荷、激励原样保留，切回即恢复。
- **驱动**（角色回答"谁扮演"，驱动回答"用什么跑"）：发生器条目、脚本节点、回放块三类并存，形态继续可插拔。

**Profile 档案**：`profiles/<名>.toml` 的角色覆盖 + 硬件映射，配合 `--profile` 让同一工程在仿真 / 台架 / CI 之间零修改切换。覆盖优先于工程里保存的激活状态；按总线名 + 节点名解析，错配**整份拒绝**，绝不只生效一半。

**DBC 自动重载 × 角色**：外部改库触发重载后，为模拟节点补建新增报文的条目但**不自动激活**——"不发送"这条约束同样适用于外部编辑与工程恢复。

## 实体表与三类驱动

- **节点的表示**：Web 没有独立的 Network 页。Buses… 的 Nodes chip 是角色开关（模拟/离线），Generator… 按节点分组列出条目与回放块，Scripts… 里绑定节点；三处都读同一份核心节点/角色模型，没有第二份拓扑。
- **回放块**：一份录制日志 + 过滤器（按发送节点或 id 列表；节点发送表优先取模型的 FRAME-PORT 关系，无模型才回退 DBC），测量启动时装载队列、把时间归一化到首帧记 0，随后与发生器共用仿真时钟按录制间距发送；文件通道到工程的映射按 cluster id 记录，播放时才解析成当前路号。**仅仿真模式生效**——回放模式下日志本身就是信号源，块保持静默。块流量照常进入聚合、负载、规格与触发：它们就是总线流量。装载失败停用块并在状态行报错；新块默认停用。
- **派生信号**：脚本一行发布"名字 + 本节点算出的值"，脚本语言就是求值器，不另造第二套表达式引擎。发布为合成订阅流，键空间前缀高于一切真实 id，绝不与帧信号的键重复；会话上限约束不同名数量（防脚本循环造名）。
- **计算通道**：工程级 `DerivedDef` 表达式同样由 core 按步采样，键为 `derived:<id>`；Variables 窗口只负责编辑，曲线/Monitor/Data/State/触发器和脚本共用这条订阅流。编辑器把 `[reference]` 的解析结果存成 `sources`，core 优先使用 pinned key，缺失时才按当前订阅和总线名回退。

## 触发层与录制

条件的电平语义是这套东西的核心：**信号类条件跟随自己那一路的帧**（解不出值的一帧不动电平），**出现类条件每次运行锁存一次**（手动 Re-arm 或"清空 Trace"动作重置），**超时类每步扫描**并复用规格监视的宽限比较——所以触发器与规格的掉线判定从不冲突。

求值在每步帧循环最前，触发帧本身被写入录制文件。动作里"发送反应帧"引用的是生成器条目而非快照，所以规则在条目被编辑后依然有效；缺失条目是 no-op，不是错误。条件求值器的锁存保证反应规则对自身输出不成环。

## 工程持久化约定

- 工程是单文件 JSON，DBC 与描述文件路径相对工程目录，可整体移动。
- **格式只有当前版本**：新增字段带默认值，未知枚举码只丢该条不炸全局；不保留旧版本工程字段的迁移。
- **恢复不发送**：生成器条目与仿真节点恢复后静默，回放块默认停用，由用户显式开启（CLI 无头仿真是唯一例外，按文件里的 active 位武装）。
- **会话状态不写入工程**：硬件连接与所用端口号、游标位置、Trace 选中行——它们指的是这一轮测量里的位置，新一轮测量开始时就会清空。

## Web 宿主与前端

- **单进程本地服务**：axum 只监听本机（默认 `127.0.0.1:2010`）。`GET /api/state` 返回 DTO 快照；`POST /api/command` 把 `WebCommand` 翻成 `BusCommand`——默认值、合法性、总线写入都留在 core。catalog / scripts / nodes / debug / recording 等按需端点只是同一份状态的投影。
- **快照只读、写入集中**：前端轮询状态（10 Hz，表格/曲线走 `epoch/seq` 增量），从不改写后端数据；用户动作一律产出 `Command`，由 `app.tsx` 的 `run()` 发出。新增命令要同时落到 `WebCommand`、TypeScript `Command` 与调用点，并补一条无头测试。
- **前端状态分层**：跨会话的布局/标签/游标/列宽/Panel book 存 localStorage 与工程 `web` 段；组件本地只放草稿、弹窗与选中态。Trace 用手写固定行高虚拟化，曲线用 canvas 抽稀，没有表格/图表组件库。
- **文件交换**：浏览器上传经 `/api/upload` 落到 per-user 数据目录，导出经 `/api/download` 取回；不提供任意主机路径读取。`.rxpanel` 与脚本文本在前端序列化，不经过后端。

## Panel 操作页

- **模型**：`panelPage.ts` 的控件注册表声明每类控件的创建、字段、最小/默认尺寸与补丁（Button / Value / Bar / Gauge / Lamp / Toggle / Setpoint）；页面是固定 8px 网格画布，坐标按格保存，多页面 book 随 workspace 走。Setpoint 用 `target` 区分 SysVar 与信号；Button 的 `writes` 是随页面保存的信号预设；旧页面里的 Numeric（无 target）与 Setpoint（旧 kind）在加载时迁移，持久格式只剩一种可编辑控件。
- **绑定与能力**：`panelBinding.ts` 是纯选择器层——解析 source、SysVar、色段、量程比例、弧线路径、运行中的动作集合与禁用原因；PagePanel 只负责渲染与编辑命令。
- **右键**：Edit 下控件、空白画布与页签各有一套上下文菜单（复制/删除；粘贴/添加/撤销；页面重命名/复制/导出/删除），统一 `role="menu"` 与 ↑/↓/Home/End/Esc，Esc 只关菜单；右键按下不触发拖动。
- **执行链**：按钮的 **On click** 三选一、互斥——**Write signals** 走 `panel_write_signals` → `BusCommand::PanelWriteSignals`，逐项调用同一个写入实现并汇总失败（会话帧无法回滚，所以不做原子失败），不碰仿真；**Send message** 走 `panel_send_frame` / `panel_send_fr_frame` / `panel_send_eth_frame`，校验总线/地址/长度后发一条原始报文：CAN 帧排进本步的接收队列，像生成器帧一样计数、解码、录制并进入已连接硬件；FlexRay 帧按槽声明长度补齐后只注入本会话；Ethernet 按矩阵 VLAN/EtherType 与固定 MAC 注入本会话 flow，长度必须与帧声明一致；CAN 已知报文带 `physical` 时改由 `signals` 编码：按目录信号夹取写入、未写信号取声明初始值，载荷宽度用报文 DLC；FR/ETH 的 physical 走同一组 `signals`，宽度用槽/矩阵的声明长度；**Script action** 走 `run_panel_action` → `on panel_action`（可带数值参数）。启动/停止/暂停等仿真控制只保留在顶部工具栏，不再由面板按钮发送 `PanelAction`；组合逻辑由脚本实现；Setpoint 的 SysVar target 写 `set_sys_var`，信号 target 统一走键寻址的 `panel_write_signal`（`SigKey` 的 Can/Fr/Eth/Derived）：CAN 按统一模型夹取、用 `encode_payload` 写进 generator 基载荷、摘掉该信号的波形源并注入一帧；FlexRay 仍用描述决定当前 cycle 的占用帧，信号位置与编码取模型 plan，并只在本次测量内注入一帧；Ethernet 按模型帧与 plan 编码，用矩阵 VLAN、`ethertype_hint`（缺省 `0x88B5`）和固定本机管理 MAC 注入一个 TX 会话帧，匹配与回读走现有 flow 解码；派生信号直接拒绝。两种 target 提交后都可带值触发同名动作。目录里既没有声明范围（max ≤ min）时按不夹取处理，与后端一致。
- **回读**：Setpoint 把目标信号按 Read 订阅（`select_signal read=true`），用同一份序列显示总线实际值；前端记录自己添加的 key，控件改绑/删除时只回收这些订阅，用户手动 Plot/Read 的信号不动。这就是面板唯一自动订阅的入口。
- **文件**：`.rxpanel` 由前端序列化，导入严格校验（类型/画幅/最小尺寸/重叠）后才作为新页面追加，绝不静默丢弃。
- **测试**：模型、选择器与导入导出有 Vitest；动作、参数与写信号有 Rust 无头测试（真实 core）；交互用浏览器 + CDP 实机走查。

## 验收三分

- **判定逻辑**用无头测试自动证明：命令组合仿真、录制回读、导出、回放、线程冒烟都在 `cargo test` 里覆盖，产品路径每一步都要过"读经快照、写经命令"。
- **Web 界面**用 `npm run build`（TypeScript + Vite）和浏览器实机检查覆盖：主标签页、虚拟滚动、曲线抽稀与弹窗交互都要在 1280×800 / 1024×768 下实际打开确认。逻辑测试挡住数据错误，构建挡住类型错误，二者都挡不住的交互问题只能靠这一步。
- **真实交互**（点击、拖拽、列宽与滚动映射、弹窗里按钮的实际效果）没有完整的自动化测试，只能人工或 CDP 脚本确认：面板级改动要"打开每个标签页、点开每个弹窗"逐一确认。
- **Vector 台架**用 `ROXY_VECTOR_BENCH=1 cargo test vector_bench_loops -- --ignored --nocapture` 自动跑：两根对连的物理口按经典 500 kbit/s 与 FD 500/2M、5M、8M（64 字节、BRS）双向对发，按帧 id 过滤同一总线上的其他流量；物理拔插仍只能人工。

计时类断言一律同机对照（同一轮里先量一个基线再比），不用绝对阈值；缺测试数据的用例必须失败，不许跳过。规矩写在 CI 配置顶部。
