# 架构文档

roxy-can 的结构、关键决策与不变式。用法见 `README.md` 与 `docs/usage.md`，还没做的事见 `TODO.md`。

## 总体分层：核心线程 + 命令/快照边界

```
前端（UI 线程，60 fps 渲染）
   │  写：BusCommand → mpsc 收件箱（单入口）
   │  读：Snapshot ← Arc 信箱（try_lock，拿不到沿用上一帧，永不阻塞）
   ▼
BusCore（bus-core 线程，事件驱动）
   信道/DBC · 仿真时钟 · 发生器 · 帧源 · trace 环 · 聚合
   订阅与采样缓存 · 规格/触发器 · 录制器 · 回放 · 硬件端口
```

- **归属划分**：核心拥有全部总线状态与执行；前端拥有窗口布局与桌面、弹窗与草稿态（数字/源码/路径的未提交草稿）、文字节流、状态行文案。边界记录在 `BusCommand`（事件）与一组原子旋钮（步长/容差/宽限等连续量，前端每帧写、核心每圈读）。
- **双驱动**：产品用线程驱动，测试与 CLI 用手摇驱动（命令同步执行、时钟手动推进），所以全链都能在 `cargo test` 里跑。核心对前端的隐式直读在线程驱动下当场 panic——前端对总线的每一条读写都必须"读经快照、写经命令"。
- **纪律**：每步结束代码可编译、测试全绿、程序可用、可发版；重构期间冻结新功能。

## 核心时钟模型：事件驱动，不用固定步长

信号值全是时间的解析纯函数（任意时刻直接求值，无需积分），固定网格只有代价没有收益。事件只有两类：发生器条目的周期 TX 槽位、外来帧（回放日志顺序到达 / 硬件到达）。核心睡到最近死线（兜底一个短超时以接收命令），醒来排空→推进到当前时刻→有变化就发布快照（至多约 60 次/秒）；空闲即休眠。

- **时间戳永不量化**：槽位保留精确微秒，值在槽位时刻求值。核心超跑（醒来晚了）按原始时间戳顺序补发——正确的数据晚到，好过准时的失真数据。
- **暂停不停车**：只翻标志、重算死线。
- **唤醒精度**：Windows 默认定时器粒度不可用，需要把系统时钟分辨率拉到 1 ms；对 ≥10 ms 周期，±1 ms 抖动可接受。

## 数据共享：共享分块 + 写时复制

快照每秒最多发布约 60 次，历史数据的发布代价曾是瓶颈，所以订阅采样缓存与 trace 环都是"封存分块（只读共享，引用计数）+ 活跃尾部"的结构：克隆只是块引用计数加一条尾部拷贝，写侧改动走写时复制，绝不惊动 UI 持有的块。直播采样走增量追加，回填才走全量展平。

trace 超过容量时**不丢弃**最旧的帧，而是追加写入临时归档文件；导出先回放归档再写热环，所以导出的日志覆盖整段运行。归档创建失败就降级为纯裁剪，并在界面上如实提示。

## 两套编号空间，永远不要合并

CAN 的地址是 `(通道, id, 帧类)`，FlexRay 的地址是 `(路/cluster, 槽)`。两个空间各自编号，`(0,5)` 既是 CAN0 的 id 5 也是 FR0 的槽 5，所以**任何把两者拼成一张表的键都必须带协议标签**：聚合、规格、订阅信号键、触发条件、录制过滤、手选集合都是枚举化的键，而不是共享的数字。

一条相关的身份规则：**cluster 索引是身份，不是列表位置**。BLF 按帧里的 cluster 号盖章、脚本里打的是 `fr_sig(1, …)`、录制过滤打的是 `FR1:5`，所以删除一路绝不重编号其余各路；空出来的号交给下一次添加。

## 仿真节点

- **常驻核心**：节点挂在核心上，绑定一条信道。测量启动时从源码重编译：主块初始化全局 → `on start` → 周期定时器惰性武装。帧分发挂在步循环里；脚本产出的发送条目由核心成帧压进同一批处理，与触发器的 Send 同机制，因此节点会收到自己发的帧。
- **防失控**：每回调有指令预算与递归深度上限；出错的节点熔断停跑（日志留痕），重新 Apply 或重启测量恢复。`print` 走节点日志环经快照发布。
- **外部调用解析链**：内建表（编译期解析，无动态派发）→ 进程内注册表（外部仿真元件）→ 节点私有钩子。未认领的名字落运行时错误，字节码格式不因任何一条缝改变。
- **定时器**：周期定时器（错过收敛为一次触发加重同步）+ 命名一次性定时器（任意回调可武装、触发即失效）。控制操作在回调结束后排空应用，在非定时器回调里改周期记告警。

## 帧键：标准/扩展分家

同数值的标准帧与扩展帧是**两个不同的报文**：DBC 表、聚合、规格、订阅信号键全部带帧类位。脚本与生成器按"id ≤ 0x7FF 标准、> 0x7FF 扩展"划类，`send`、`on message`、信号编解码同一规则；裸 id 场景（显示、兜底查名）标准优先、扩展兜底。已知妥协记在 `TODO.md`。

## 角色模型：事实源、角色、驱动三分离

"DBC 节点 ≠ 仿真节点"的不一致在模型层面消灭——三个正交概念各有一个事实来源：

- **总线拓扑**：唯一事实源是 DBC（FlexRay 侧则是集群描述）。节点名单、报文与信号、发送关系全部从文件推断，程序绝不重复声明。
- **执行角色**：两态声明，只能命名库里已有的节点——**模拟**（本工具以它名义发车）/ **离线**（不模拟；真实节点的流量经 Real bus 的挂接通道进来，或来自回放块）。**缺省即离线**，restbus 无需配置，存档里只记对缺省的偏离。切入模拟为节点补建发生器条目；退出只停发——条目、载荷、激励原样保留，切回即恢复。
- **驱动**（角色回答"谁扮演"，驱动回答"用什么跑"）：发生器条目、脚本节点、回放块三类并存，形态继续可插拔。

**Profile 档案**：`profiles/<名>.toml` 的角色覆盖 + 硬件映射，配合 `--profile` 让同一工程在仿真 / 台架 / CI 之间零修改切换。覆盖优先于工程里保存的激活状态；按总线名 + 节点名解析，错配**整份拒绝**，绝不半套生效。

**DBC 自动重载 × 角色**：外部改库触发重载后，为模拟节点补建新增报文的条目但**不自动激活**——"不发车"这条红线同样适用于外部编辑与工程恢复。

## 实体表与三类驱动

- **Network 视图**是网络的表示：拓扑按总线分段，点节点打开它自己的详情（角色、生成器条目、响应规则、绑定的脚本、回放块）。行的次序是纯派生态。
- **回放块**：一份录制日志 + 过滤器（按发送节点或 id 列表），测量启动时装载队列、把时间归一化到首帧记 0，随后与发生器共用仿真时钟按录制间距发车。**仅仿真模式生效**——回放模式下日志本身就是信号源，块保持静默。块流量照常进聚合、负载、规格与触发：它们就是总线流量。装载失败停用块并在状态行报错；新块默认停用。
- **派生信号**：脚本一行发布"名字 + 本节点算出的值"，脚本语言就是求值器，不另造第二套表达式引擎。发布为合成订阅流，键空间前缀高于一切真实 id，绝不与帧信号撞键；会话上限约束不同名数量（防脚本循环造名）。

## 触发层与录制

条件的电平语义是这套东西的核心：**信号类条件跟随自己那一路的帧**（解不出值的一帧不动电平），**出现类条件每次运行锁存一次**（手动 Re-arm 或"清空 Trace"动作重置），**超时类每步扫描**并复用规格监视的宽限比较——所以触发器与规格的掉线判定永不打架。

求值在每步帧循环最前，触发帧本身被录进文件。动作里"发送反应帧"引用的是生成器条目而非快照，所以规则在条目被编辑后依然有效；缺失条目是 no-op，不是错误。条件求值器的锁存保证反应规则对自身输出不成环。

## 工程持久化约定

- 工程是单文件 JSON，DBC 与描述文件路径相对工程目录，可整体移动；定时自动保存，异常退出后恢复。
- **向后兼容靠缺省**：新增字段一律带默认值，旧工程照读；未知枚举码只丢该条不炸全局；新增码追加在表尾，旧版本读到新码按"丢源不丢条"处理。存档里带一个 `schema_version`，未来格式迁移以它分支，不与 crate 版本挂钩。
- **恢复不发车**：生成器条目与仿真节点恢复后静默，回放块默认停用，由用户显式开启（CLI 无头仿真是唯一例外，按文件里的 active 位武装）。
- **会话状态不落盘**：硬件挂接与所用端口号、游标位置、Trace 选中行——它们指的是这一轮测量里的位置，新一轮一清就没人站在那儿了。

## 验收三分

- **判定逻辑**用无头测试自动证明：命令组合仿真、录制回读、导出、回放、线程冒烟都在 `cargo test` 里覆盖，产品路径每一步都要过"读经快照、写经命令"。
- **绘制路径**由 headless imgui 冒烟床跑：imgui 不挂渲染器也能产出完整逻辑帧，所以每个窗口的 draw 都会真的执行一遍。这层必须有——曾经所有逻辑测试全绿、编辑器却在绘制里崩。
- **真实交互**（点击、拖拽、列宽与滚动映射、弹窗里按钮的实际效果）没有床，只能人工眼见：窗口级改动要"打开每个窗口、点开每个右键菜单"逐一眼见为实，编译期逼不出来的是没人打开过的窗口。

计时类断言一律同机对照（同一轮里先量一个基线再比），不用绝对阈值；缺测试数据的用例必须红，不许跳过。规矩写在 CI 配置顶部。
