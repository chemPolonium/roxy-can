# 架构文档

roxy-can 的代码结构、关键设计决策与不变式。使用方法见 `README.md` 与 `docs/usage.md`；剩余工作见 `TODO.md`。

## 总体分层：核心线程 + 命令/快照边界

```
前端（UI 线程，60 fps 渲染）
   │  写：BusCommand → mpsc 收件箱（App::send 单入口）
   │  读：Snapshot ← Arc 信箱（try_lock，拿不到沿用上一帧，永不阻塞）
   ▼
BusCore（bus-core 线程，事件驱动）
   信道/DBC · 仿真时钟 · 发生器 · FrameSource · trace 环 · 聚合
   订阅与采样缓存 · 规格/触发器 · 录制器 · 回放
```

- **归属划分**：核心拥有全部总线状态与执行（信道/DBC、仿真时钟、发生器 `TxMsg`+`ValueSrc`、`FrameSource`、trace 环、聚合、负载、订阅与 `SampleCache`、规格/触发器、录制器）；前端拥有窗口布局与桌面、弹窗与草稿态（数字/源码/录制路径草稿）、文字节流、状态行文案。边界记录在 `BusCommand`（事件）与 `BusKnobs`（stride/容差/宽限等连续量，原子量，前端每帧写、线程每圈读）。
- **双驱动**：`CoreDrive::Threaded`（产品，`App::new` 起线程）与 `CoreDrive::Manual`（`App::headless()`，send 同步、tick 手摇，测试与 CLI 用）。`Deref` 仅在 Manual 下交出核心，Threaded 下 panic——隐式核心访问由编译期逼出。
- **纪律**：每步结束代码可编译、测试全绿、程序可用、可发版；前端对总线的每一条读写都必须"读经快照、写经命令"，产品路径不留 Deref 直读。

## 核心时钟模型：事件驱动，不用固定步长

信号值全是时间的解析纯函数（`sim::eval_phys` 在任意时刻直接求值，无需积分），固定网格只有代价没有收益。事件只有两类：发生器条目的周期 TX 槽位、外来帧（回放日志顺序到达/硬件到达）。核心睡到最近死线（`FrameSource::next_deadline`，`recv_timeout` 封顶 10 ms 兜命令），醒来 `drain → step_to(now) → 脏则发布`（至多 ~60/s）；空闲即休眠。

- **时间戳永不量化**：槽位保留精确 µs，值在槽位时刻求值；核心超跑（醒来晚了）按原始时间戳顺序补发——正确的数据晚到，好过准时的失真数据。记录端只认帧内时间戳，迟发在曲线与统计里不可见。
- **暂停不停车**：只翻标志、重算死线。
- **唤醒精度**：Windows 默认定时器粒度 ~15 ms 不可用，需 `timeBeginPeriod(1)`（或等效）拉到 1 ms；对 ≥10 ms 周期 ±1 ms 抖动可接受。如将来有更高要求，可加"最后 <1 ms 自旋收尾"开关（未实现，见 TODO）。
- **线程退出**：前端丢弃命令发送端（mpsc 断线）即退出。

## 数据共享与性能（ sealed chunks + COW）

快照每秒最多发布 ~60 次，历史数据的发布代价曾是瓶颈。三处大头全部改为**共享 + 增量**：

- **订阅采样缓存**：`SampleCache` 内部为封存分块（`chunks: Vec<Arc<Vec<点>>>`，只读共享）+ 活跃尾部（512 点封存一次，封存即移动零拷贝）。`Clone` 从深拷贝变为"块引用计数 + 尾部拷贝"；写侧改动走 `Arc::make_mut`，绝不惊动 UI 持有的块。直播采样走 O(增量) 追加；重叠/回退 backfill 走 O(总量) 展平-合并-重分块。
- **trace 环**（`src/trace.rs`）：同样的分块结构，发布 = 块引用计数 + 一条尾部拷贝；前端冻结视图 `TraceView` 支持双向迭代（新帧在上）。超过容量的帧不丢弃而是**追加写入临时归档文件**（定长 84 字节记录，核心线程整批写、每进程独立文件）——Export Trace 先回放归档再写热环，导出覆盖整段运行；归档创建失败降级为纯裁剪并在界面如实提示。
- **满载探针**（`perf_snapshot_publish_under_load`，`#[ignore]`，release 手动跑）：6 路订阅 × 72 000 点/路 + 5 万帧满环，发布一帧从旧设计的 4 511.6 µs 降到最坏 12.4 µs（当轮全脏）、空闲 3.7 µs（纯指针换手）——最坏 **362×** 便宜。

## 仿真节点架构

- **常驻核心**：`ScriptNode`（稳定 id）挂在 `BusCore.nodes`，绑定一条信道。测量启动时从源码重编译：跑主块初始化全局 → `on start` → 周期定时器惰性武装（首周期后触发）。帧分发挂在 step 循环里；脚本 `send` 产出的 outbox 条目由核心成帧压进同一 buf 同步处理（与触发器 Send 同机制，节点会收到自己发的帧）。
- **防失控**：每回调 10 万指令预算 + 256 层帧深上限；出错的节点熔断停跑（日志留痕），重新 Apply 或重启测量恢复。`print` 走节点日志环（200 行封顶）经快照发布。
- **外部调用解析链**：主机内建表（`HOST_FNS`，编译期解析为 `CallHost`）→ 进程内注册表 `script::register_extern`（外部仿真元件，名字被认领则其 `Ok(None)` 落 nil）→ 节点私有钩子 `HostExternFn`（`set_sig`/`get_sig` 走信道 DBC 编解码；返回 `Ok(None)` = 未认领 = 运行时错误）。字节码格式不因任何一条缝改变。
- **定时器**：周期定时器（`on timer <ms>`，错过收敛为一次触发加重同步）+ 命名一次性定时器（`on timer "名"`，`set_timer` 任意回调可武装、触发即失效）。timer 控制经 `TimerOp` 队列在回调后排空应用；在非定时器回调里使用 `set_period`/`stop_timer` 记告警。
- **持久化**：`NodeCfg`（name/channel/source/enabled）随工程走 `SetNodes` 整表命令恢复，id 重新铸造；GUI 打开工程不启动节点流量（安全语义），CLI `--project` 显式仿真时按文件里的 active 位重新武装。

## 帧键模型：标准/扩展分家

同数值的标准帧与扩展帧（如 0x100 两类共存）是**两个不同的报文**：

- DBC 表以 `MsgKey = (u32, bool)` 为键（messages/order/value_tables/周期声明/浮点声明/扩展复用规则）；`decode_signals(&CanFrame)` 按帧类精确匹配。
- 聚合 `aggs: (u8, u32, bool)`、规格 `Spec::rows: (u8, u32, bool, Kind)`；订阅信号键 `SigKey = (u8, u32, bool, String)` 贯穿采样与全部观测窗口。
- 脚本与生成器按"id ≤ 0x7FF 标准、> 0x7FF 扩展"划类（`send`、`on message`、`encode_signal` 同一规则）；裸 id 场景（显示、兜底查名）标准优先、扩展兜底。
- 已知妥协记录在 `TODO.md`（裸 id 展示层对双类只列一条；数值 ≤ 0x7FF 的扩展帧无法从脚本寻址）。

## P0 角色模型：事实源、角色、驱动三分离

"DBC 节点 ≠ 仿真节点"的不一致在模型层面消灭——三个正交概念各有一个事实来源：

- **总线拓扑**：唯一事实源是 DBC。节点名单、报文与信号、发送关系全部从库推断，程序绝不重复声明（旧版 `sim_nodes` 双源清单已废除）。
- **执行角色**：`NodeRole` 三态声明，只能命名 DBC 已有的节点——`Simulated`（本工具以它名义发车）、`Monitor`（在总线只收不发，零成本）、`Absent`（不在仿真总线）。**缺省即 Absent**：映射里没有条目就是离线，restbus 无需配置；`node_roles` 只存对缺省的偏离（`Absent` 条目直接删除）。切入 Simulated 为节点补建发生器条目并发车；退出只停发——条目、载荷、激励原样保留，切回即恢复。
- **驱动**（角色回答"谁扮演"，驱动回答"用什么跑"）：发生器条目、脚本节点、回放块三类驱动并存，形态继续可插拔。

- **Profile 档案**：`profiles/<名>.toml` 角色覆盖 + CLI `--profile <名>`（须配 `--project`）——同一工程在 simulation / bench / CI 零修改切换。覆盖优先于工程里保存的条目激活状态；按总线名+节点名解析，错配（未知总线/节点/角色词）**整份拒绝**，绝不半套生效。TOML 由 `toml_edit` 直读（依赖树已有，parse-only，手工提取两个字符串一个词）。
- **DBC 自动重载 × 角色**：外部改库触发重载后，为 Simulated 节点补建新增报文的条目但**不自动激活**——"不发车"红线同样适用于外部编辑与工程恢复。

## 实体表与三类驱动

- **Entities 窗口**是网络的表示：扁平 imgui 表格（无图形化拓扑），每行一个实体——DBC 声明节点 / 脚本节点 / 回放块，kind 徽标 + 行内状态（角色三态下拉 / 运行开关）；点击行打开该实体自己的界面（Network 视图选中节点 / Nodes 窗口 / Replay Blocks 窗口），行右键可插入或删除。行的次序是纯派生态：按总线、库内声明序、节点名。
- **回放块**（`ReplayBlock`）：一份录制日志 + 过滤器（按 DBC 发送节点或 id 列表，皆空 = 全部），测量启动时装载队列并把时间归一化到首帧记 0，随后与发生器共用仿真时钟按录制间距发车；**仅仿真模式生效**——回放模式下日志本身就是信号源，块保持静默，绝无二次投递。块流量照常进聚合、负载、规格与触发：它们就是总线流量。装载失败（路径无效/过滤后无帧/节点不在库中）停用块并在状态行报错；新块默认停用。声明 `BlockCfg` 随工程保存，恢复即重载队列（坏路径在打开工程时暴露）。
- **派生信号**：脚本 `emit_value("名", 表达式)`——脚本语言就是求值器，不另造第二套表达式引擎。发布为合成订阅流，键 `(ch, EMITTED_ID_BASE|node_id, false, 名)`（前缀 0x8000_0000 高于一切真实 id，绝不与帧信号撞键），在信号选择树"派生信号"分组按所属节点列出，Graphics / Data / State Tracker 照常选用。会话上限 256 个不同名（防脚本循环造名的 runaway 守卫）。

## 触发层与录制

- 四类条件（`TriggerCond`）：信号越阈 `SignalCross`（沿触发、电平跟随该报文自己的帧）、`IdPresent`/`ErrorFrame`（帧驱动，每运行锁存一次）、`CycleTimeout`（每步扫描，复用规格的宽限比较——触发器与 Dropped 判定永不打架）。信号条件携带帧类位。
- 动作（`TriggerAction`）：开始/停止录制（带 256 帧预触发上下文；停止后滚 32 帧才闭文件）、Send（反应帧带触发帧信号镜像，网关式转发）、插入标记（Graphics 竖线）、清空 Trace（聚合/规格/录制不动）。动作码随工程持久化，未知码只丢该条。
- 触发求值在每步帧循环最前，触发帧本身被录进文件；条件求值器的电平锁存保证反应规则对自身输出不成环。

## 工程持久化约定

- 工程是单文件 JSON（`.rxproj`），DBC 路径相对工程目录，可整体移动；30 秒自动保存，异常退出后恢复。
- **`schema_version`**：现值 1，随每次保存写入；更早的文件缺字段读作 0——未来格式迁移以此为分支依据，不与 crate 版本挂钩。未知角色词/枚举码等仍按"丢条不炸全局"处理。
- 向后兼容靠 serde 缺省：新字段一律 `#[serde(default)]`（如信号键的 `ext`、触发器的 `ext`、回放块的 `ids`），旧工程照载；恢复时未知 kind 码只丢该条不炸全局。旧版 `sim_nodes` 名单读入时迁移为 Simulated 角色，文件不再回写该字段（`skip_serializing`）。
- 新增波形状/枚举码追加在 `KINDS` 末尾，旧版本读到新码按约定丢源不丢条目。
- 工程恢复不发车：生成器条目与仿真节点恢复后静默，回放块默认停用、恢复时装载队列但不激活新流量，由用户显式开启（CLI `--project` 仿真为例外，按文件 active 位武装）。

## 开发约定与教训

- **红线**：每步测试全绿、程序可用、可发版；重构期间冻结新功能；纯移动不改逻辑，编译器和测试兜底。
- **验收两分**：判定逻辑用无头测试自动证明；控件行为（`src/ui/*` 无 imgui 测试床）只能人工眼见——窗口级清扫要按"打开每个窗口 + 点开每个右键菜单"逐一眼见为实，编译期逼不出来的是没人打开过的窗口。
- **无头测试床**：`App::headless()` 双驱动 + 命令/快照边界让全链（命令组合仿真、录制回读、导出、回放、线程冒烟）都在 `cargo test` 里覆盖；线程驱动下每个产品路径都要过一遍"读经快照、写经命令"，冒烟测试逐步覆盖启动与恢复路径。
- **教训**：批量改测试用 Edit 工具，PowerShell 重写文件会引入 BOM、以系统码页误读 UTF-8 中文注释成乱码、甚至吞掉行首属性——已两度翻车，PowerShell 只许做只读字节检查；并行测试的临时文件必须显式设独立路径（默认路径会在 CWD 派生同名录制文件互相碰撞）。
